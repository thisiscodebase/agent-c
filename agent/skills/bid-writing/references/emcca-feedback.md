# EMCCA feedback — mandatory on every delivery answer

Apply all five rules to every tender question that describes delivery, outreach, or beneficiary experience.

## 1. Clear end-to-end user pathways

Always describe the full beneficiary journey step-by-step:

**Awareness → Entry → Diagnostic → Routing → Delivery → Progression → Exit**

Avoid isolated components; present a coherent, navigable service. Make transitions between stages explicit.

## 2. No assumed knowledge

Do not reference programmes, infrastructure, or partners without explaining what they are and how they function in delivery. Write every answer as if the evaluator has zero prior knowledge of CodeBase.

## 3. Explicit accessibility and inclusion model

Every delivery answer must state how the service is accessible to:

- digitally excluded users
- underserved or underrepresented groups
- time-poor or geographically dispersed participants

Include practical mechanisms (offline routes, assisted onboarding, flexible delivery, inclusive design).

## 4. Multi-channel outreach beyond existing networks

Demonstrate how new users are reached beyond core ecosystem partners. Include channels, target groups, and methods (e.g. community partners, local authorities, libraries, targeted campaigns).

## 5. Operational clarity over conceptual language

Prioritise "how it works in practice" over high-level descriptions. Use structured flows, numbered steps, and concrete delivery detail.
